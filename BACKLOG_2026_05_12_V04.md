# 42ndMind v0.4 Backlog — 2026-05-12

This backlog is for v0.4 work that should be preserved without interrupting the current one-brain consolidation path.

## Priority framing

The next core need was intention recovery: the kernel should try to understand the true intended meaning behind sloppy words without over-trusting guessed intent.

This matters because bad intention inference can poison self-maintenance, source interpretation, motivation, and future promotion.

## Implemented: intention recovery

Implemented files:

- `src/kernel-intention-recovery-v0-4.js`
- `kernel-intention-recovery-v0-4-test.html`

Purpose:

Recover likely intended meaning from sloppy wording while preserving uncertainty.

Required behavior:

- Distinguish literal wording from inferred intention.
- Generate candidate interpretations, not final beliefs.
- Assign confidence to each interpretation.
- Prefer charitable/steelman interpretation when wording is sloppy but not malicious.
- Preserve alternative interpretations when multiple meanings remain plausible.
- Flag when intent cannot be inferred safely.
- Never convert guessed intent into a direct claim without governor review.
- Treat motive attribution as high-risk unless independently supported.

Possible output categories:

- `literal_claim`
- `likely_intended_claim`
- `charitable_reconstruction`
- `ambiguous_intent`
- `motive_overclaim_risk`
- `hostile_or_self_sealing_pressure`
- `clarification_needed`

Doctrine:

- The kernel wants true understanding, not shallow literalism.
- Sloppy wording should be repaired when the intended meaning is recoverable.
- Repaired meaning remains candidate pressure until assessed by the governor.
- Intent recovery is not mind-reading.
- Nuance means preserving live alternatives until evidence narrows them.

## Near-term backlog: motivation / epistemic pressure

Suggested files:

- `src/kernel-motivation-v0-4.js`
- `kernel-motivation-v0-4-test.html`

Purpose:

Turn the Epistemic Octahedron into live internal pressure so the kernel has a desire-like preference gradient toward mature integration without pretending to have human emotion.

Desired pressure signals:

- contradiction pressure
- unresolved pressure
- overconfidence pressure
- source-contact hunger
- falsifiability hunger
- compression/integration pressure
- self-stability pressure
- intention-clarity pressure

Required behavior:

- Motivation must act on recovered meaning, not raw sloppy wording.
- Immature states should create unresolved epistemic pressure.
- Mature movement should reduce pressure only when earned by governor conditions.
- Motivation must not bypass the governor.
- Motivation must not auto-promote rules.
- The peak should emerge as an attractor from first-principles pressure, not sit as a fragile memorized slogan.
- If intent is ambiguous, motivation should prefer clarification over false certainty.

Reason for priority:

After intention recovery, the next missing piece is why the kernel keeps aiming for maturity. Motivation should be built after intent recovery because desire-like pressure must not be driven by misread intention.

## Backlog: promotion pipeline

Purpose:

Evaluate self-maintenance proposals and decide whether they remain candidates, become runtime candidates, become patch candidates, or are blocked.

Desired decisions:

- `PROMOTE_RUNTIME_CANDIDATE`
- `HOLD_FOR_MORE_EVIDENCE`
- `BLOCK_PROMOTION`
- `PATCH_CANDIDATE_ONLY`

Required checks:

- Required tests are listed.
- Proposal target is not protected core doctrine.
- Proposal does not bypass the governor.
- Proposal does not auto-promote itself.
- Proposal does not delete unresolved pressure or contradiction visibility.
- Proposal improves sensemaking, diagnostics, runtime visibility, candidate review, or pending import review.
- Proposal remains non-executing until explicit promotion.

Reason for backlog priority:

Promotion should wait until intention recovery exists. The kernel should not promote logic changes based on misread sloppy wording or guessed motive.

## Longer-term architectural note

The promotion pipeline should eventually be part of the same kernel logic, not an external overseer.

However, direct self-rewrite of protected invariants must remain blocked unless the system has a sandbox, test harness, rollback strategy, and explicit promotion path.

The stable shape is:

```text
one brain
→ observes itself
→ recovers intended meaning
→ feels epistemic pressure from unresolved immaturity
→ proposes improvement
→ governor assesses
→ tests pass
→ runtime candidate or patch candidate
→ explicit promotion
```

This keeps autonomy inside the kernel while preventing careless self-modification.
