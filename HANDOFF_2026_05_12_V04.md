## Current architectural state

The system now has a tested v0.4 decision flow:

```text
input
→ KernelBrainV04.process(input)
→ sensemaking adapter if needed
→ intention recovery where sloppy wording needs repair
→ consistency and probability checks where claim sets need calibration
→ shared epistemic governor
→ preflight adapter if command-shaped
→ one final decision surface
```

This is not yet full runtime integration into `llm-brain-v0-3.html`.

## Important doctrine

The goal is not layers of dormant logic that activate on special triggers.

The goal is one movement law:

```text
input enters
meaning is assessed
pressure is formed, held, capped, blocked, or allowed
kernel state updates only through explicit runtime binding
```

Adapters may parse or format. They must not own belief movement.

## Git write rule

Use the SHA write trick:

1. Fetch file first and use current blob SHA.
2. `update_file` with full replacement content and that SHA.
3. Wait for `commit_sha`.
4. Fetch file back and verify exact change.
5. Make only one small change at a time.

Never trust a write until fetch-back verifies it.
